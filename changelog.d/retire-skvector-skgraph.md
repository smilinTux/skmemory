- chore(backends): Qdrant (skvector) and FalkorDB (skgraph) are retired for good (SKMEM-P5-02). Removed `skvector_backend.py`, `skgraph_backend.py`, `graph_queries.py` (FalkorDB Cypher templates), `endpoint_selector.py` and the `routing` CLI group, `setup_wizard.py` and the `setup` CLI group (Docker deploy of the retired stack), the `skvector`/`skgraph` extras, the `skvector_*`/`skgraph_*` config fields and HA endpoint fields, `--skvector-*` CLI options, the recall-collection Qdrant/FalkorDB sync in `LazyMemoryLoader`, and the four recall scripts that drove them. The graph is AGE only and the vector tier is pgvector only. `SKMEMORY_VECTOR_BACKEND=skvector|qdrant|skgraph|falkordb` now fails fast with a retirement message (non-zero exit on the CLI, red `health`). Stale `skvector_*`/`skgraph_*`/endpoint keys or `backends_enabled` entries in `skmemory.yaml`, and stale `SKMEMORY_SKVECTOR_*`/`SKMEMORY_SKGRAPH_URL` variables, are ignored with a one-time warning and never fail, so old node configs cannot break session hooks. Failed-sync rows are now keyed `vector`/`graph` (legacy `skvector`/`skgraph` rows are still retried and cleared). Downstream: `skcapstone` pins `skmemory[skvector]` (pip warns about the missing extra, install still works) and its `sync_watcher.py`/`memory_adapter.py` import the removed modules inside ImportError/Exception guards.
