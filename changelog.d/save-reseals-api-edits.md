Fixed: `save` on the sqlite, file and vaulted backends re-seals a memory whose sealed fields (title, content, emotional) were edited in process after it was loaded. The memory must carry the hash of the verified stored copy of the same id; anything else (new memory, unsealed, failing predecessor, a different incoming hash) is saved as given and still verifies as tampered, and a file edited outside the API never passes through `save`. Each re-seal logs a warning naming the fields.
