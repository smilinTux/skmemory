A restricted reader no longer learns the ids of hidden memories through link fields. `MemoryStore.redact_links` (same visibility rule as `history()`) drops hidden `related_ids`, `parent_id`, `supersedes_id`, `metadata.superseded_by`, `possible_conflict_with`, `write_triage`, `decomposition.parent_id`, `promoted_id`, `chunk_memory_ids` and `observation.evidence_ids`. It is applied only at output boundaries (MCP `memory_recall`, `memory_search`, `memory_list` and CLI `recall`, `task-pack show`); `recall`, `search` and `list_memories` still return the real record so internal read-modify-write code never saves a redacted copy. `store.promote`, `PromotionEngine.promote_memory`, `refresh_observation`, `sweep_observations` and `write_observation` now refuse under a declared reader. Owner output is unchanged (SKMEM-P0-21).
