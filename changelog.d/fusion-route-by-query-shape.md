Search fusion now routes the pinned head by query shape (SKMEM-P1-08). A deterministic, no-LLM classifier (`fusion.route_query`) calls a query identifier-ish when it carries a digit, underscore or host-shaped token, or a token that is rare in the local FTS index (new `SQLiteBackend.term_doc_freq`); those keep the lexical top-3 pin. Question-shaped and stopword-heavy queries are natural-language and pin the vector top 2 (`SKMEMORY_FUSION_VECTOR_PIN`), with the interleave fill still including lexical; if the vector arm did not contribute, the lexical pin stands. `SKMEMORY_FUSION_ROUTE=auto|lexical|vector` (default `auto`) forces a route, and `FusionResult.route` records it. `skmemory.eval.live_bench --routes` runs the candidate once per route on the same queries.
