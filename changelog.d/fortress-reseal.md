Added: `skmemory fortress reseal`, a re-seal for memories proven to be victims of a fixed sealing bug (a seal taken over a title with whitespace `Memory` strips on load, or a promoted copy that kept its source's hash). Dry run by default: it lists each id, the reason, the old and new hash and the proof, and writes nothing. `--write` re-seals, re-proves each memory at write time, and logs every re-seal (`fortress-reseal.jsonl` and the audit chain). Edited content, changed titles, foreign hashes, failing parents and signed files are never touched. `--write` needs `--id <id>` (repeatable) or `--all`. A promoted copy also needs its source to name it back (`promoted_id`), so a hand-edited file cannot borrow a donor's hash, and nothing is re-sealed where a signature sidecar is expected but missing.
