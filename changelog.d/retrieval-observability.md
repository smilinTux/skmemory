Each fused search appends one line to `<agent>/logs/retrieval.jsonl` (rotated at 5 MB, 3 kept): per-arm status, hit count and latency, the spread of the fused RRF score, and a query hash and word count, never the query text. Writes go through a bounded queue and a daemon thread, so a slow or failing disk cannot slow or fail a search. `memory_health` gains `retrieval.arms`, read from the last 100 logged searches (so it works across short-lived CLI runs), and returns `degraded` when an arm errors or times out (latest attempt, or 10 percent or more of at least 5 attempts). A config-disabled arm (graph by default) never degrades. An arm with zero hits for 100 searches is `quiet`, not dead, and degrades only if its backend probe also fails. Set `SKMEMORY_RETRIEVAL_LOG=off` to disable. Only the fused path is logged (SKMEM-W-02).
