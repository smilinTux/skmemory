- fix(pg-migrate): the skmem-pg SQL (`schema.sql`, `migrations.txt`, `NN-*.sql`, `verify-*.sql`) moved from `deploy/skmem-pg/` to the package directory `skmemory/pg/` so it ships in the wheel; on a PyPI install `skmemory pg migrate` previously saw an empty manifest and never applied schema v2. Compose now mounts `skmemory/pg` as the initdb source. `skmemory pg migrate SCRIPT` honours an existing filesystem path as given instead of looking its basename up in the manifest directory. DSN passwords are redacted in every plan, log and error (shown as `***`) and passed to psql/pg_dump via `PGPASSWORD`, not argv. With a DSN and no host `psql`/`pg_dump`, the runner falls back to `docker exec` on the default container with a clear message.
